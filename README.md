# Epic Trade

Bybit · Binance · OKX 무기한 선물용 통합 차트. 한 화면에 **추정 청산맵 + 스마트 머니 컨셉 + 엘리엇 파동**을 겹쳐 본다.
차트 엔진은 TradingView의 오픈소스 [Lightweight Charts](https://github.com/tradingview/lightweight-charts) 5.1.0, 데이터는 세 거래소의 공개 API(키 불필요).

## 실행

설치형 웹앱(PWA)이다. 빌드 과정 없이 정적 파일만으로 동작한다.

**로컬**

```
node server.js      # → http://localhost:8787
```

**웹 배포 (GitHub Pages)** — `.github/workflows/pages.yml` 포함. 저장소 Settings → Pages → Source를 "GitHub Actions"로 지정하고 `main`에 병합하면 배포된다. 배포 주소를 PC 크롬이나 휴대폰 브라우저에서 열고 "앱 설치 / 홈 화면에 추가"를 누르면 앱처럼 쓸 수 있다.

주의: 호스팅된 주소에서는 로컬 프록시가 없으므로 브라우저가 거래소 REST를 직접 호출한다. 각 거래소가 이를 허용(CORS)하는지는 **실제 환경에서 확인되지 않았다.** 막히면 화면에 오류가 표시되며, 그 경우 로컬 실행을 쓰거나 별도 프록시가 필요하다.

## 화면 구성

- 왼쪽: 그리기 도구(추세선 · 수평선 · 사각형 · 피보나치 · 롱/숏 포지션 · 자 · 자석 · 삭제)
- 상단: 심볼 · 타임프레임 · 레이어 스위치 3개(청산 / SMC / 엘리엇) · 설정 · 정보 패널
- 설정(슬라이더 아이콘): 세부 항목 켜고 끄기, 청산 계산 기간, 히트맵 강도, 스윙 길이, 파동 크기, 수동 카운트
- 정보 패널: 시장 지표, 청산 밀집 구간, SMC 요약, 엘리엇 단계·무효화·목표가, 실시간 청산

## 기능

| 영역 | 내용 |
|---|---|
| 청산 히트맵 | 시간×가격 추정 청산 레벨, 3대 거래소 합산. 기간 24시간~3개월 |
| 청산맵 | 현재 남은 레벨의 가격대별 막대(레버리지 티어별) + 롱/숏 누적선, 상위 밀집 구간 목록 |
| 실청산 | 세 거래소 청산 스트림의 실제 체결(버블 + 피드) |
| SMC | BOS / CHoCH, 오더블록, FVG, EQH/EQL(유동성), 프리미엄/디스카운트 |
| 엘리엇 | 자동 카운트(ATR 지그재그 + 절대 규칙 검증), 수동 카운트(클릭), 무효화 레벨, 피보나치 목표 |
| 그리기 | 추세선, 수평선, 사각형, 피보나치 되돌림, 롱/숏 포지션(손익비 2:1), 자. 심볼별 저장, 타임프레임을 바꿔도 유지 |
| 기타 | OI 보조창, 거래량, 펀딩비, 롱/숏 계정비(Bybit), 과거 봉 자동 추가 로딩 |

## 단기 방향 점수 (실험)

정보 패널 맨 위 칸. 다섯 요인을 −1~+1로 매겨 동일 가중 평균한다(`js/signal.js`). 가중치를 과거 데이터에 맞춰 조정하지 않는다.

| 요인 | 계산 |
|---|---|
| 모멘텀 | 종가와 20봉 지수이동평균의 거리(ATR 단위) |
| 구조 | 마지막 BOS/CHoCH 방향 |
| 체결 압력 | 최근 10봉의 거래량 가중 봉 몸통 방향 |
| OI·가격 | 6봉 동안 가격과 OI가 같이 늘면 그 방향, OI가 줄면 약하게 |
| 청산 쏠림 | 현재가 ±3% 안의 추정 청산 물량이 더 많은 쪽 |

점수 절댓값이 0.25 미만이면 "중립"이다. 같은 칸의 표는 **지금 불러온 봉에서 이 점수가 실제로 맞았는지**를 잰 것이다: 1·4·12봉 뒤 종가 방향 적중률, 95% 신뢰구간, 왕복 수수료 0.11%를 뺀 신호당 평균 순수익. 신뢰구간 하한이 50%를 넘고 순수익이 양수일 때만 "우위 관측"으로 표시한다.

이 점수의 예측력은 실제 시세로 검증된 적이 없다. 표의 숫자가 유일한 근거이며, 표본이 화면에 불러온 봉으로 한정되고 OI·청산 요인은 데이터가 있는 구간에서만 계산된다.

## 거래소 연결 방식

- 접속 주소는 `js/exchanges.js` 맨 위 `ET.config` 한 곳에 있다. 거래소가 주소를 바꾸면 여기만 고친다.
- 캔들은 설정에서 고른 거래소(기본 Bybit)에서 받는다. 그 거래소가 응답하지 않으면 나머지를 순서대로 시도한다.
- 청산맵은 거래소마다 따로 계산한 뒤 달러 금액을 그대로 더한다. 점유율 가중치 같은 고정 상수는 없다.
- **응답하지 않는 거래소는 합산에서 빠지고 정보 패널에 "미연결"로 표시된다. 가짜 데이터로 대체하지 않는다.** 세 곳 모두 실패하면 빈 차트와 오류만 나온다.
- 브라우저의 직접 호출이 막히면 `node server.js`의 `/proxy/<거래소>/…`로 자동 재시도한다.

## 반드시 알아야 할 한계

- **실제 거래소 데이터로 검증되지 않았다.** 개발 환경에서 세 거래소 접속이 불가능해, 공식 문서의 응답 형식을 흉내 낸 모의 데이터로만 시험했다.
  - Bybit·OKX 형식은 공식 문서에서 확인했다.
  - Binance의 OI 이력(`openInterestHist`)·청산 스트림(`forceOrder`) 필드와 WebSocket 주소(`wss://fstream.binance.com/stream`)는 문서로 재확인하지 못했다. Binance가 선물 WebSocket 주소 체계를 바꿨다는 정황이 있으니, 연결이 안 되면 `ET.config.BINANCE.ws`부터 확인한다.
  - 각 거래소 OI 스냅샷의 시각 기준(구간 시작/끝)이 같다고 가정했다. 다르면 봉 하나만큼 어긋난다.
- **청산맵은 Coinglass 데이터가 아니다.** OI 증가분을 신규 진입으로 보고 레버리지별 청산가를 계산한다(`js/liqmap.js`). 레버리지 분포(10x 30% · 25x 35% · 50x 25% · 100x 10%), 롱·숏 동일 비중, 최저 티어 유지증거금률(Bybit 0.5%, Binance·OKX 0.4%)은 **가정값**이다. 금액은 상대 비교용이다.
- OI 이력 제공 범위가 거래소마다 다르다(Binance 약 30일, OKX 최근 1,440개). 3개월 범위에서는 일부 거래소가 짧게 반영될 수 있다.
- OKX 청산 채널은 전체 청산이 아니라 일부만 제공한다(OKX 문서 명시).
- 실청산은 접속한 이후 체결분만 쌓인다. 브라우저 localStorage에 최근 3,000건 저장.
- 엘리엇 자동 카운트는 규칙을 통과한 후보 1개일 뿐이다. 같은 차트에 유효한 카운트는 여러 개 존재한다.
- SMC 신호는 확정봉만 사용해 리페인트되지 않지만, 스윙 피벗은 설정 길이만큼 늦게 확정된다.
- 그린 도형은 선택·삭제만 된다. 끌어서 옮기거나 크기를 바꾸는 기능은 없다.
- 어떤 지표도 수익성이 검증되지 않았다. 백테스트는 포함되어 있지 않다.

## 테스트

```
node tests/unit.js   # 분석 로직 (합성 데이터). 방향 점수가 미래 봉을 참조하지 않는지도 확인
node tests/e2e.js    # 브라우저 통합 (Playwright 필요, 거래소 응답은 모의 데이터)
```

통합 테스트는 네 가지 상황을 확인한다: 세 곳 모두 연결 / 일부 미연결 / 차트 거래소 미연결 시 다른 거래소로 전환 / 전부 미연결 시 빈 차트.
